# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Common Development Commands

- **Install dependencies**:
  ```bash
  pip install -r requirements.txt
  ```
- **Start the full system** (master, workers, load balancer, controller):
  ```bash
  python main.py start
  ```
- **Start individual components**:
  - Master only: `python main.py master`
  - Worker `<id>` (e.g., worker 1): `python main.py worker 1`
  - Load balancer only: `python main.py lb`
  - Controller only: `python main.py controller`
- **Stop all components**:
  ```bash
  python main.py stop
  ```
- **Ingest RAG documents**:
  ```bash
  python ingest.py
  ```
- **Run benchmark suite** (example low‑concurrency run):
  ```bash
  python benchmark.py --single --workers 4 --concurrency 20 --requests 200
  ```
  Adjust `--workers`, `--concurrency`, and `--requests` as needed.
- **Run the test suite**:
  ```bash
  pytest tests/ -v
  ```
  - Run a single test file: `pytest tests/test_load_balancer.py -v`
  - Run a specific test pattern: `pytest tests/test_rag.py -v -k "test_basic_retrieval"`

## High‑Level Architecture

- **Client (`benchmark.py`)** sends HTTP POST `/query` requests.
- **NGINX Load Balancer** (port 8000) routes traffic to workers using round‑robin or least‑connections strategies.
- **Workers** (ports 8001‑8004) are FastAPI services that perform:
  - LLM inference via Ollama (`llm/inference.py`).
  - Retrieval‑augmented generation using ChromaDB (`rag/retriever.py`).
  - Response caching and GPU usage monitoring.
- **Master (`master/monitor.py`, port 9000)** tracks worker health (heartbeat every 5 s) and provides a `/schedule` endpoint for coordination.
- **Load Balancer Controller (`lb/app.py`)** manages worker enable/disable, switches routing strategies, and aggregates status metrics.
- **ChromaDB vector store** holds embeddings generated by Ollama (`ingest.py` reads docs/*.txt, embeds with `nomic-embed-text`).
- **Supporting scripts** (`client/load_generator.py`, `client/stress_test.py`) drive load tests used by the test suite.

The system can be launched entirely via `python main.py start` or component‑wise for debugging. Tests rely on the services being up (see the "Running Tests" section in the README).
